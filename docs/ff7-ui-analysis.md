# FF7 UI 參考分析（Final Fantasy VII 主選單）

**資料來源**：`scratchpad/ff7-measurements.md`（由參考截圖逐像素取樣）。
**量測基準**：原始截圖 1280×720 RGB，裁切出遊戲畫面 `crop box = (104, 28, 1054, 626)` → **950 × 598 px**。
**座標慣例**：以下所有 x/y 皆為 viewport 相對座標（0,0 = 950×598 裁切區左上角）。百分比 = x、w ÷ 950；y、h ÷ 598。
**規則**：本文所有數值皆取自量測檔。凡量測檔未涵蓋的項目，一律標記「**未量測**」，不推測、不補值。

### A.3 必須原樣保留的三個細節

1. **`next level` 全部小寫**——不是 `Next Level`，也不是 `NEXT LEVEL`。開頭的 `n` 是小寫。
2. **`Limit level 1` 只有 L 大寫**——`level` 是小寫，後面接一個獨立的數字 `1`。不要寫成 `Limit Level 1`。
3. **`Shinra Bldg.` 帶尾隨句點**——`Bldg.` 的句點是原文的一部分，不可省略；`Shinra` 與 `Bldg.` 之間為單一空格。

另註：HP／MP 數值中的斜線後**有一個空格**（`465/ 465`，不是 `465/465`），這是原文寫法，照抄。

### A.4 未量測項目（不猜）

- HP／MP 數值行下方那條細橫線（截圖可見）——**未量測**（顏色、粗細、x 範圍皆無取樣資料）。
- `next level` 與 `Limit level 1` 標籤的 ink 起始座標——**未量測**。
- 所有數值字串的字框（寬高）——**未量測**，僅量了 Item/Magic/Materia/Save/Quit/Cloud/Time/Shinra Bldg. 八組。
- 角色頭像縮圖區的位置與尺寸——**未量測**。

### C.2 建議的漸層宣告

```css
--ff7-panel-gradient: linear-gradient(
  135deg,
  #0057ad 0%,
  /* --ff7-blue-highlight，面板左上角 */ #003592 22%,
  #001c74 48%,
  /* --ff7-blue-middle */ #000a55 74%,
  /* --ff7-blue-dark */ #000026 100% /* --ff7-blue-edge，面板右下角 */
);
```

角落模型：TL `#0057AD`、TR ≈ `#000B5D`、BL ≈ `#000E85`、BR ≈ `#000026`。因為 **TR ≈ BL**，用 135deg 的單一對角線性漸層就能重現原始的雙線性色場，不需要 radial 或多層疊加。

`#003592` = rgb(0, 53, 146)，是 22% 位置的內插停點（由 (200,40) `#00459A`、(740,12) `#02368C`、(90,250) `#003198` 推得，非單點取樣，信心中等）。

### C.3 三個必須說清楚的前提

1. **漸層是完全不透明的。** 沒有 alpha、沒有 glassmorphism、沒有 `backdrop-filter`、沒有任何 blur。截圖裡的面板是實色填充，背後的遊戲畫面完全不透出來。
2. **最亮在面板的左上角，最暗在右下角。** 每個面板都有自己獨立的一份漸層（cmd、Time/Gil、location 各自從自己的左上角重新亮起來），不是整片畫面共用一個大漸層。
3. **這與「邊緣暗、中心亮」的直覺假設剛好相反。** 常見的 vignette 式假設（四周壓暗、中央提亮）在這張截圖裡**不成立**：量測顯示的是單向對角漸層。實作時不要套 vignette、不要在中央加亮斑。

**逐邊不對稱（照實記錄）**：量測檔的摘要說「四個面板的堆疊相同」，指的是**面板之間**相同，不是**四條邊**相同。原始掃描顯示：

- **上緣**沒有明確的內側暗線：main 上緣是 `#111111` → `#9C9C9C` → `#DFDFDF`（峰）→ `#C6C6C6` → 混色 → 藍，第 5 層缺席。

### D.2 可直接貼用的 CSS 配方

```css
:root {
  /* 邊框層（見 §C.1） */
  --ff7-border-shadow: #252523;
  --ff7-border-middle: #7c7e7b;
  --ff7-border-highlight: #e7e7e7;
  --ff7-border-light: #cfcfd1;
  --ff7-border-midlight: #939391;
  --ff7-border-dark: #272823;

  /* 面板底色（見 §C.2） */
  --ff7-panel-gradient: linear-gradient(
    135deg,
    #0057ad 0%,
    #003592 22%,
    #001c74 48%,
    #000a55 74%,
    #000026 100%
  );

  /* 邊角階梯量（參考解析度下 = 5px） */
  --ff7-chamfer: 5px;
}

/* 唯一的可重用元件：FF7Panel */
.ff7-panel {
  position: relative;
  background: var(--ff7-panel-gradient);

  /* 不用 border，整條框由 inset box-shadow 疊出來 */
  border: 0;
  /* 明確禁止圓角：原圖的角是階梯狀，不是圓弧 */
  border-radius: 0;

  /* 由外而內：spread 遞增，最外層寫在最前面（先寫的畫在上面） */
  box-shadow:
    inset 0 0 0 1px var(--ff7-border-shadow),
    /* 第 1 層：1px 近黑外緣   */ inset 0 0 0 3px var(--ff7-border-middle),
    /* 第 2 層：2px 中灰       */ inset 0 0 0 4px var(--ff7-border-highlight),
    /* 第 3 層上半：1px 峰值白 */ inset 0 0 0 5px var(--ff7-border-light),
    /* 第 3 層下半：1px 近白   */ inset 0 0 0 6px var(--ff7-border-midlight),
    /* 第 4 層：1px 淺灰       */ inset 0 0 0 7px var(--ff7-border-dark); /* 第 5 層：1px 內側暗線   */

  /* 階梯 chamfer：八邊形，切掉四個角 */
  clip-path: polygon(
    var(--ff7-chamfer) 0,
    calc(100% - var(--ff7-chamfer)) 0,
    100% var(--ff7-chamfer),
    100% calc(100% - var(--ff7-chamfer)),
    calc(100% - var(--ff7-chamfer)) 100%,
    var(--ff7-chamfer) 100%,
    0 calc(100% - var(--ff7-chamfer)),
    0 var(--ff7-chamfer)
  );
}
```

**spread 對應厚度的算法**：`inset 0 0 0 Npx` 從 padding box 邊緣往內畫 N px 的實心環，先列的畫在後列之上。所以第 k 層的可見厚度 = `spread(k) − spread(k−1)`：1 / 2 / 1 / 1 / 1 / 1 = 合計 7 px，與量測的硬層總厚一致。

**為什麼是 clip-path 而不是 border-radius**：量測到的左上角是 `y=30 → x=83`、`y=32 → x=81`、`y=35 → x=78` 的 45° 階梯（Time/Gil 的左上角同樣是 `431→668`、`434→666`、`436→663`），是**直線斜切**，不是圓弧。`border-radius` 會產生弧線與弧線上的漸變抗鋸齒，與原圖的像素階梯不同，**明確排除**。

**要真階梯（非平滑斜邊）時**：`clip-path` 的斜線本身會被瀏覽器抗鋸齒成平滑斜邊。若要 1 px 一階的硬階梯，把單一斜線換成 5 段折線即可（以左上角為例，其餘三角鏡射）：

```css
clip-path: polygon(
  5px 0,
  5px 1px,
  4px 1px,
  4px 2px,
  3px 2px,
  3px 3px,
  2px 3px,
  2px 4px,
  1px 4px,
  1px 5px,
  0 5px,
  /* …其餘三角以相同方式鏡射… */ 0 5px
);
```

### D.3 落地約束

- 這整段（漸層 + 六層 inset shadow + chamfer）必須收在**單一可重用的 class / component：`FF7Panel`**。四個面板（main / command menu / Time-Gil / location）都只是同一個 `FF7Panel` 加上不同的位置與尺寸，**不得**各自複寫一份邊框樣式。
- `--ff7-chamfer` 的 5px 是「參考解析度（950×598）下」的值。若整個 UI 等比縮放，這個值要跟著縮放，否則邊角比例會走樣。
- 面板外側**沒有**額外的 drop shadow（量測未發現）。不要加 `box-shadow`（非 inset）或 `filter: drop-shadow()`。
- `image-rendering: pixelated` 對 CSS 畫出來的框沒有作用；它只用在點陣圖素材（見 §F）。

| 逐字寬度（`Materia`）        | M 708–725（18）／a 730–739（10）／t 744–751（8）／e 757–765（9）／r 770–775（6）／i 780–781（**2**）／a 786–795（10） |
| 逐字 advance                 | M 22 ／ a 14 ／ t 13 ／ e 13 ／ r 10 ／ i 6                                                                           |
| 字距（letter-spacing）       | **實質為 0**；字墨之間的 4–6 px 是 sidebearing，不是 tracking                                                         |
| 行高 / line pitch            | 指令選單 **32 px**（≈ 1.15）；Time/Gil **38 px**（≈ 1.36）                                                            |
| 建議 font-size               | **27–28 px**（webfont cap height ≈ 0.72 em 時，可得 20 px cap）                                                       |
| text-shadow offset           | **+2 px x / +2 px y，blur = 0**                                                                                       |
| 整詞字寬                     | Item 77 px／Magic 64／Materia 88／Save 51／Quit 47／Cloud 59／Time 51                                                 |

> `Item` 的 x 範圍在量測檔記為 680–756，但手指游標的 bbox 是 x 642–689，**與 Item 那一列重疊**。因此 680 這個左緣幾乎確定被游標像素污染；`Item` 真正的 ink 左緣應與 Magic / Materia / Save / Quit 一致，落在 **x=708**。做版面時用 708。

**比例結論**：M/cap = 22/20 = 1.10、a/cap = 14/20 = 0.70、i/cap = 6/20 = 0.30。這是一套**高度比例化、非常窄、字身高於字寬**的字，`i` 的墨跡只有 2 px 寬。任何等寬字都直接出局。

### E.2 邊緣是不是點陣？

**是點陣，但被放大過。** 判斷依據：字緣有明顯的方形階梯（點陣特徵），但每一階的轉折帶著 1–2 px 的灰階過渡（向量字不會有階梯；純點陣放大也不會有灰階過渡）。量測檔的推論是：**原始為點陣字，以約 1.48× 放大並套用雙線性（bilinear）內插**，所以階梯還在、但每一階被抹糊了。

實務後果：

- 文字**不要**套 `image-rendering: pixelated`——那是給游標點陣圖用的（見 §F）。網頁文字用一般的向量算繪即可。
- 目標觀感是「樸素、不圓滑的點陣／窄體字」，而不是「銳利的 1:1 像素字」。字緣稍微柔一點反而更接近原圖。

### E.3 最接近的合法 web font 替代方案（排名）

| 名次 | 字體                                          | 判斷                                                                                                                                                                                       |
| ---- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | **Jersey 10**                                 | 這批候選裡最窄、字身最高的比例化點陣字，M/a/i 的相對 advance 最接近量到的 22/14/6；小寫字身高與 cap 的比例也對得上。仍是替代品，不是原字。                                                 |
| 2    | **Jersey 15**                                 | 同家族、同骨架，但字幅略寬、筆畫略粗；20 px cap 下筆畫會超過量到的 2–3 px 一點，整體字寬會比原圖溢出。                                                                                     |
| 3    | **Handjet**                                   | variable pixel 字，可調元素形狀與大小（ELGR/ELSH），有機會把字身壓窄逼近量測值；缺點是預設偏方正、需要額外調參，且元素間有可見縫隙，與原圖的實心筆畫不同。                                 |
| 4    | **Micro 5**                                   | 極窄、極高，比例方向正確；但它是 5 px 網格字，在 20 px cap 下每個「像素」約 4 px 寬，遠粗於量到的 2–3 px 筆畫，細節會整片糊掉。                                                            |

**Press Start 2P 明確不使用**：它是等寬字，每個字都佔滿 1 em，筆畫粗且方正。與量測到的「比例字、advance 22/14/13/13/10/6、筆畫僅 2–3 px、字身窄長」三項特徵**全部相反**。它會讓畫面看起來像 NES 而不是 FF7 的 PlayStation 選單。

### E.4 關於「原字是什麼」——證據不足

**本文不宣稱已經辨識出原始字型。** 手上只有一張被放大過、帶雙線性模糊的截圖，可用的證據是八個詞的字框與一個詞（`Materia`）的逐字 advance；這不足以唯一確定一套字型。上面列的每一個候選都是**替代品**，不是原字。

因此，字型必須留成可換的：

```css
:root {
  --ff7-font-family: "Jersey 10", "Jersey 15", "Archivo Narrow", sans-serif;
}
```

之後若找到更接近的字，只改 `--ff7-font-family` 一處即可，不得把字型名稱硬寫進各元件。

### E.5 排版規則（必須遵守）

1. **`LV` / `HP` / `MP` 三個標籤用 cyan `--ff7-text-cyan` (`#23DFEA`)**，其餘所有選單文字一律用 off-white `--ff7-text-white` (`#E7E9E6`)。數值（`13`、`465/ 465`、`4:52:23`、`6293`）屬於「其餘」，是 off-white。
2. **投影是硬邊的**：`text-shadow: 2px 2px 0 #0B0B18`。**blur radius 必須是 0**，不准有柔邊、不准有多層發光。
3. **`letter-spacing: 0`**（或 `normal`）。量測顯示字距實質為零，不要為了「復古感」加正字距。
4. **不可讀起來像粗體現代 dashboard 字**：字重用 regular，禁用 `font-weight: 600/700`、禁用 `-webkit-text-stroke`、禁用大寫轉換（`text-transform` 一律不用——原文的大小寫已經是設計的一部分，見 §A.3）。
5. 行高：指令選單 `line-height: 32px`（≈1.15）；Time/Gil 區塊 `line-height: 38px`（≈1.36）。這兩個值不同，不要統一。

## F. 手指游標分析（Hand cursor analysis）

### F.1 Sprite 量測

| 項目                   | 值                                                                       |
| ---------------------- | ------------------------------------------------------------------------ |
| bounding box           | x **642–689**、y **22–51**                                               |
| 尺寸                   | w **48 px**、h **30 px**                                                 |
| 百分比（相對 950×598） | x 67.58%、y 3.68%、w 5.05%、h 5.02%                                      |
| 指向                   | **向右**（食指朝右伸出）                                                 |
| 指的目標               | 指令選單的 `Item` 那一列（`Item` ink 為 y 19–38，游標 y 22–51 與之重疊） |

### F.2 顏色構成

| 區域         | 量測色                | RGB                                 |
| ------------ | --------------------- | ----------------------------------- |
| 白色本體     | `#F0F0F2`             | rgb(240, 240, 242)                  |
| 灰色內部陰影 | `#9A9AA0` … `#6E6E78` | rgb(154,154,160) … rgb(110,110,120) |
| 深色像素外框 | `#141420` … `#000000` | rgb(20,20,32) … rgb(0,0,0)          |

三層結構：白色手掌／手指本體 → 指節與掌心的灰階內陰影 → 一圈 1 px 的深色像素描邊把整個 sprite 圈起來。背景**必須透明**。

### F.3 與指令選單盒的關係

游標是**獨立元素，不是盒子的一部分**，而且它**壓在盒子的左邊框上**：

- 指令選單外框左緣 **x=668**（八列複測確認，見 B.2），左邊框佔 x 668–676，內側藍色場自 x=677 開始。
- 游標 bbox 為 x 642–689：左端 642 比盒子外框左緣 668 還往左 **26 px**（伸在盒子外的黑色遊戲背景上），右端 689 已越過內緣 677，**指尖進入藍色場約 12 px**。
- 也就是說：游標橫跨「盒外背景 → 金屬框 → 藍色場」三個區域。**這個跨越必須保留**，不可以把游標塞進盒子內距裡。
- 縱向：游標 y 22–51（中線 ≈36），`Item` 的 cap 範圍是 y 19–38（中線 ≈28）。游標比文字**往下多伸 13 px**，兩者並非垂直置中對齊。

實作上，游標要用 `position: absolute` 疊在 `FF7Panel` 之上（`z-index` 高於面板），而不是放進選單項目的 flow 裡。

### F.4 素材約束（硬性）

- **背景透明**（PNG alpha）。
- **不是 emoji**（不得用 👉 / ☞ 之類的字元）。
- **不是作業系統的滑鼠指標**（不得用 `cursor: pointer` 或任何系統游標形狀代替）。
- **不是平滑的向量圖示**（不得用 Font Awesome / Material Icons 的手指圖示，也不得自己畫平滑 SVG）。
- 出貨路徑：**`public/assets/ff7-hand-cursor.png`**，由參考截圖的 x 642–689 / y 22–51 區域裁切而來，**只清掉周圍背景**，sprite 本身的像素一個都不改（不重繪、不描邊、不補色、不做去鋸齒）。
- 顯示時加 `image-rendering: pixelated`——量測檔明確指出這個屬性適用於游標 sprite（但**不**適用於文字，見 §E.2）。

### F.5 動態規格

- **兩幀階梯式水平擺動**：水平位移 **3–5 px**（建議 4 px），只有兩個狀態，中間不插值。
- **禁止**：垂直位移、旋轉、縮放、平滑 easing（不得用 `ease` / `ease-in-out` / `cubic-bezier`）、透明度變化。
- 時間函數用 `steps()`，讓兩幀之間是瞬間切換。

```css
.ff7-hand-cursor {
  position: absolute;
  width: 48px; /* 量測值 */
  height: 30px; /* 量測值 */
  image-rendering: pixelated;
  animation: ff7-hand-bob 0.8s steps(1, end) infinite;
}

@keyframes ff7-hand-bob {
  0%,
  49.99% {
    transform: translateX(0);
  }
  50%,
  100% {
    transform: translateX(-4px);
  }
}

@media (prefers-reduced-motion: reduce) {
  .ff7-hand-cursor {
    animation: none;
  }
}
```

- **`prefers-reduced-motion: reduce` 時必須停止動畫**（`animation: none`），游標停在第一幀。
- **動畫週期未量測**：單張靜態截圖無法測出擺動頻率。上面的 `0.8s` 是佔位值，不是量測結果；若要精確還原需要影片素材。
